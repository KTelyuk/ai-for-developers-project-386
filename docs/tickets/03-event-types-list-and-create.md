# 03. Типы встреч: владелец создаёт, гость видит список

Status: ready-for-agent
Blocked by: 02

## Что сделать

Первый сквозной срез через контракт, бэкенд и фронтенд. Владелец в `/admin/event-types` видит свои типы встреч и создаёт новый: название, описание, длительность из списка 15/30/45/60. Гость на странице бронирования видит список типов встреч с названием, описанием и длительностью, выбирает один и видит блок «Информация» (название, описание, длительность, часовой пояс Алматы). Без типов встреч гость видит, что записаться пока нельзя.

Эндпоинты `GET /api/event-types`, `GET /api/event-types/{id}`, `POST /api/admin/event-types` — по таблице и правилам валидации из `docs/spec.md`.

## Критерии приёмки

- [ ] Контракт описывает три эндпоинта и модель типа встречи; SDK и типы бэкенда перегенерированы.
- [ ] Создание с пустым названием, длительностью вне списка или слишком длинными полями — `400` с `VALIDATION_ERROR`; форма показывает ошибку под полем.
- [ ] Неизвестный `id` — `404`.
- [ ] Созданный владельцем тип встречи появляется в списке у гостя.
- [ ] Ответы API сверяются со схемой OpenAPI в тестах.
- [ ] В гостевом интерфейсе нет ссылок на `/admin`.
- [ ] Раскладка адаптивна с первого экрана: от 360 px без горизонтальной прокрутки.
