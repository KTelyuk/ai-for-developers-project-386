# Карта: спецификация сервиса

## Destination

Этап 1 из README закрыт: `docs/spec.md` (роли, сценарии, параметры расписания, правила пересечений и отмены, модели данных, эндпоинты и коды ответов) и тикеты в `docs/tickets/` на этапы 2–7, по которым агент реализует сервис без новых вопросов. Реализация начинается после карты.

## Notes

- Функционал и правила — строго по README («Сценарий», «Правила и ограничения», «Параметры расписания», «Устройства»). При любом расхождении побеждает README.
- За основу экранов взят Cal.com: раскладка и порядок шагов (информация слева, календарь, слоты, затем форма). Экраны подстраиваются под README, Cal.com не копируется целиком.
- Уже решено в README и не выносится на карту: стек, параметры расписания, черновой список эндпоинтов, отсутствие авторизации, уведомлений и внешних календарей.
- Словарь — `GLOSSARY.md` (запись, бронирование, страница бронирования, страница записи); решения — `docs/adr/`. Новые термины и решения фиксируются по ходу, через domain-modeling.
- Тикеты `grilling` — навыки grilling и domain-modeling; `prototype` — навык prototype; `research` — навык research в субагенте, находки на ветке `research/<name>` без PR.
- Язык документов и интерфейса — русский.
